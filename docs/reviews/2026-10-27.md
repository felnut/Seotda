# 전체 코드 및 브라우저 검토 — 2026-10-27

기준: `500e34c`의 현재 코드 전체. 사용자가 커밋 간 비교 대신 전체 검토를 선택했다.
별도 이슈 명세와 `docs/agents/issue-tracker.md`는 없어 README와 대화에서 요청한 동작을 기준으로 삼았다.
모든 아래 수정은 작업 디렉터리에 있으며, 이 검토 이후 커밋·배포는 하지 않았다.

## Standards

1. **P1 — 잘못된 소켓 입력으로 서버 종료.** `create-room`에 `null`을 보내면 구조 분해에서 처리되지 않은 예외가 발생해 격리 서버가 exit 1로 종료됐다. `server/socketPayload.ts`와 Socket.IO 미들웨어에서 이벤트별 필드 타입·열거형·인덱스를 검증한다. 수정 후 동일 요청은 거부되고 정상 방 생성은 계속된다.
2. **P1 — 비공개 카드 식별자 노출.** 상대 카드의 본문은 숨겼지만 `id`에 월과 종류가 남았다. `server/socket.ts`에서 비공개 카드는 `hidden-0` 같은 화면용 키만 전송한다. 본인 패·공개 패·쇼다운 정보는 유지한다.
3. **P1 — 같은 소켓의 중복 좌석·방 점유.** 여러 좌석을 만들어 서로 다른 패 관점을 받거나 연결 종료 시 자리를 남길 수 있었다. 한 소켓에 한 자리만 허용하고 비동기 인증 조회 후에도 연결·방·좌석 상태를 재검증한다. 같은 자리의 중복 재접속과 퇴장 후 새 방 생성은 허용한다.
4. **P2 — 취약한 gRPC 하위 의존성.** Firebase의 Node용 Firestore 의존성에 `@grpc/grpc-js@1.9.16`이 남았다. Firebase를 다운그레이드하지 않고 기존 Admin SDK도 사용하는 `1.14.6`으로 통일했다. 설치 스크립트는 실행하지 않았다. 프로덕션 npm audit 경고는 high 4건에서 0건으로 줄었다. 실제 앱은 취약점 설명의 gRPC 서버 인증 기능을 사용하지 않으므로 직접 악용 가능성이 입증된 것은 아니다. [공식 보안 공지](https://github.com/advisories/GHSA-m9gg-hp2v-232j), [1.14.6 릴리스](https://github.com/grpc/grpc-node/releases/tag/@grpc%2Fgrpc-js@1.14.6).

## Spec

1. **P1 — 느린 로그인 복원 후 자리 복구 실패.** README의 재접속 복구와 달리 700ms 뒤 게스트로 재접속해 유효한 저장 세션을 지울 수 있었다. `useAuthState`에서 로딩과 확정된 게스트를 구분하고 인증 복원 후에만 재접속한다. 인증 오류가 나면 저장 세션을 유지한다.
2. **P1 — 네트워크 재연결 후 자리 미복구.** 마운트 때만 재접속해 새 소켓이 기존 좌석에 연결되지 않았다. `lib/rejoin.ts`에서 매 `connect`마다 복구하고 정리된 효과의 늦은 토큰 송신을 차단한다.
3. **P2 — 방 입장 버튼 잠김.** 토큰 갱신 오류와 서버 무응답에 상태 해제가 없었다. 오류 처리·15초 제한·연결 종료·화면 이탈 정리를 추가했다. 시간 초과 시 이전 연결을 재설정해 늦은 입장이 서버에 좌석을 남기지 않게 한다.
4. **P2 — 문서와 실제 기능의 불일치.** README의 정원 초과 관전 안내는 서버가 실제 허용하는 "정원이 남은 진행 중 방"으로 정정했다. 개인정보처리방침은 Google만 설명하던 내용을 실제 네 소셜 제공자와 로그인 연결 정보로 맞추고 현재 광고 중지 상태를 반영했다. 관전자 정원 정책 자체는 변경하지 않았다.

## 초기 로딩 개선

- 닫힌 메뉴·설정·테마·프로필을 미리 마운트하지 않는다. 보이지 않는 텍스트와 공유 SDK도 초기 화면에서 제외된다.
- Google SDK는 로그인 또는 계정 연결 버튼이 실제로 나타날 때만 로드한다. SDK 다운로드 중 화면을 나갔다 재진입해도 버튼이 활성화되도록 `onLoad`와 `onReady`를 함께 처리한다. 무한 폴링은 제거했다.
- 첫 화면 제목·폼·글 도입부의 투명도 진입 애니메이션을 제거했다. 카드 장식과 하단 콘텐츠 애니메이션은 유지한다.
- 실제 사용하는 Pretendard와 게임 카드·효과음은 보존했다. 배포 후 WebPageTest 재측정 전에는 전송량·LCP 개선 수치를 확정하지 않는다.
